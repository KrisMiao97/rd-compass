# 研发罗盘

帮助研发团队看清产品可能怎样改变、为什么值得考虑，以及什么条件下选择哪条路线。先完成已有证据能支持的分析，再说明关键未知。用户可只要探索方向，也可要求深入比较或准备立项评审；不要把资料清单和试验安排当作产品机会分析的替代品。

## 按任务读取与交付

- 用户想先体验时，使用 [桌面加湿器合成样例](references/synthetic-demo.json) 和正式 HTML 模版生成演示。样例中的产品、资料与工况均为虚构。按真实任务研究时另建数据文件。

- 开始研究时读取 [研究工作流](references/research-workflow.md)，确定产品开放探索、公司或路线分析、明确问题比较三种入口之一；没有三棱镜也可独立完成。
- 关键资料不足时读取 [补证与条件判断](references/evidence-and-decisions.md)，由分析者先完成可做的回查和相似机制比较。
- 撰写报告前读取 [输出设计规范](DESIGN.md)。按 [文字底稿](assets/report-outline.md) 组织内容；需要 HTML 时按 [数据约定](references/output-format.md) 使用 `scripts/render_report.py` 与 `assets/report.html` 生成自包含报告。方向数量、名称和结论都来自本次研究，不沿用个案。
- 首屏、对比、机制图、时间结论、证据索引和补证记录共用同一份结构化数据。先核查内容，再验证页面；格式校验不能代替研究复核。

## 从已有起点开始

- 只有产品、公司、路线或一批材料时，先形成有限范围的研究地图。明确纳入、排除、时间和资料边界，沿使用过程及主要技术构成寻找差异。若几个产品边界都合理，说明暂定范围并保留旁支。只有缺少的信息会实质改变研究范围且无法推知时才提问。
- 用户提到的手段默认是候选。用户或项目明确固定的手段与约束单列。先将技术观察连接到可能的产品能力与实际使用情境，目标可以随研究调整。
- 三棱镜与批量阅读是可选输入。接入时复用原任务、文献版本、原文位置与实际复核状态。独立使用时直接清点和核验原始资料。只需要公司或技术专题的证据时，不自动扩展为企业全量调查。

## 建立能回查的材料基础

仅使用用户授权的材料与数据工具。先验证检索与同件正文能取得，再按产品叫法、部件与实际功能、相邻产品或替代实现等角度扩大召回。记录检索式或描述、数据源、日期、返回量、实际筛读数、去重口径与未覆盖范围。按相关性、结构差异、时间和工况选材，不按数量或热度直接决定价值。跨地区同族或同申请公开授权版本不能当作多份独立证据。

专利目录和摘要用于找线索。形成机制结论前，核对同件公开号和版本，连贯阅读权利要求及解释该机制的完整实施段和必要附图。相关图未取得时，依赖图的细节保留未知。权项、说明书的明确披露、申请人声称效果、实际测量结果和本次推断分别标记。避免将不同实施例的可选结构合并为同一实现。对现成笔记优先提取已有内容，仅在影响方向时回查原文。区分尚未提取、尚未检查、未取得与在已查范围未披露。独立复核确实进行时才记录复核人和范围。

没有外部检索或全文时，用其他可信材料完成能支持的部分，保留未验证假设与最小补源动作。一个接口失败时，在权限和预算内尝试其他已授权来源，并记录实际取得情况，不把调用失败写成零结果。未观察到的专利方案仅表示当前资料中未观察到。研究成果不得将专利数量、申请或公开日期、文本效果宣称直接等同于采用率、成熟度、性能或市场趋势。

区分主样本、补充检索和相邻技术参照。每份关键文献注明来源、同件原文位置、是否进入统计及证据角色。补读日期与样本截止日期分开；新增对照不自动加入原分母。回查发现材质、实施例或引用位置错误时，先更正受影响的判断，不能只改善措辞。

## 从差异形成产品机会

1. 选可比方案。写清共同任务、作用对象、触发情境、工作过程及系统边界。以现有简单方案或维持现状为基线。公司专题适当补查公司外解法，路线专题适当寻找同功能替代原理。
2. 核对差异为何存在。关注功能转移、替代机理、为弥补缺陷新增的结构、条件变化、新使用情境。检查尺寸、材料、工况、成本选择和撰写口径等其他解释。年代先后仅用于描述观察顺序，继承或替代关系需要额外证据。
3. 写出具体变化。说明部件安装在哪、什么触发动作、怎样影响系统，由此可能增加何种能力，谁在什么情境中受益。每项重点方向保留原文观察、比较推导、拟改变的能力、预期用途、成立条件及最先核查的假设。新组合允许提出，标清推断起点。
4. 查找削弱判断的材料。检查同一任务的简单实现、边界工况、接口冲突、维护或制造代价。跨领域借鉴说明作用机制、介质、温度、尺度与工况差异，区分可移用、需调整和不可移用部分。

可以从需要反推技术，也可以从技术线索提出用途再检验需要。前者与 IfM 将用户及业务需要、产品和技术相连接的思路相通。后者是本 Skill 面向开放预研的应用。各方向的数量随证据和实际差异决定。

## 主动减少关键未知

出现“资料不足”“需要用户验证”或准备追加检索时，读取 [补证与条件判断](references/evidence-and-decisions.md)。先说明这个未知的不同答案会怎样改变产品方向、实现方式或研究顺序；没有影响的未知暂不追查。

1. **先回查已有材料。** 区分尚未提取与原文未披露；从批量阅读结果定位到影响判断的权项、完整实施段和附图。不能要求上游一开始把所有字段读全，也不能把上游未抽取当成原文没有。
2. **主动比较相似路线。** 在已授权来源内，按共同任务与作用机制寻找本领域替代、其他公司的做法或相邻产品。说明具体差异、适用条件和迁移障碍；同时保留简单基线与反面证据。相似专利可以帮助解释实现方式，不能代替本产品的需求和性能数据。
3. **有针对性地邀请补充数据。** 只有已有公开资料无法解决、且答案会改变判断时，向使用者说明缺哪一项数据、哪些已有记录可用、不同答案会如何改变结论，并提供“补充现有资料／继续公开技术对照／暂按条件分析”等选择。一次优先询问影响最大的事项，不索要整套资料作为开工门槛。等待期间继续不依赖该答案的工作；未回复不等于同意外发保密资料或追加费用。
4. **没有内部数据也继续分析。** 给出当前可支持的产品机会、可比实现及条件分支，明确哪部分是披露、比较推断或尚未验证的收益。只有授权、研究对象或不可替代的事实确实阻塞时，暂停受影响部分；其他分析照常交付。

每轮补证记录“关键疑问 → 已做的补读或对照 → 新发现 → 哪个判断改变或未变 → 剩余未知”。新资料不再区分候选路线、只重复同一机制，或剩余疑问确实只能由用户记录与试验回答时，结束本轮补查并给出条件结论，不无限扩搜。

## 比较路线并决定下一项证据

- 比较具体路线时，分别记录不可妥协的要求、可权衡的偏好和当前未知项。检查不同合理使用工况、供应、成本、制造与维护条件下，候选何时适用、何时失效、哪些结果会改变选择。借鉴 RAND 的适用边界与弱点分析。不编造场景概率、精确总分或工程阈值。
- 对可能改变方向的未知，写出不同答案对应的动作、能区分答案的观察或测试、所需时间资源。借鉴 NASA 决策分析中对减少不确定性的价值判断。先考虑可复用的资料回查、基线测量和可逆验证，再决定是否需要样机投入。保留高潜力的新机制探索空间。
- **值得研究**需要可解释的技术线索或机制假设、可能有意义的产品变化，以及能减少重要不确定性的下一步。**值得进入立项讨论**另外需要明确产品目标、与拟投入相称的效果和使用价值证据、替代路线与代价比较，以及可说明的资源和阶段依赖。计划中的测试和模型分析不算实测通过。

## 交付与接续

首屏先回答“发现了什么变化、由此产生什么产品机会、在什么条件下更值得考虑”，随后给出结构对照和依据。把“本轮不能排序”留在证据边界说明中；证据支持局部取舍时仍明确表达。没有成本与资源依据，不使用“最便宜”“最快”来推荐试验；没有需求证据，不按专利数量排投入优先级。

重点方向按“材料披露 → 方案差异 → 可能能力 → 成立条件 → 尚存假设”解释，标题直接写发现或判断，不机械重复五个问句。在首次涉及判断的位置说明依据，并标清推断；未实测的收益不写成已证实。对全部重点方向采用相称的分析深度，不能只为前两条给条件判断而把后两条留作口号。

把已观察到的变化、候选方向、关键假设、已完成补证、立项缺口和来源按读者的理解顺序组织。趋势说明样本范围与证据等级。公开披露只能支持有条件的技术判断。产品采用、市场速度和上市时间需要相应证据。预测可用依赖顺序与复评信号表达，时间依据缺失时保留未知。

有推进建议时写清基线、对照工况、关键指标、由谁设达标条件、结果出现后继续/修改/暂停的动作。保留依据与变化记录，遇到新证据只重审受影响判断。区分试验设计无效、某个实现失效与整个方向失去价值。探索任务可交付有依据的候选与关键疑问，不强制走到立项。证据不支持的法律、安全、量产或市场结论保持开放。

交付前按参考文件末尾的读者检查核对。HTML 报告检查桌面、窄桌面、中等屏幕和手机：图中文字须能读，主要结论不能只藏在悬停、颜色或折叠区；证据详情、筛选和打印保留完整内容。
